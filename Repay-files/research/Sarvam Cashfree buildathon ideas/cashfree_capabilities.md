# Cashfree API products and agent capabilities in sandbox (state as of 27 Oct 2026)

Method note: all facts below come from Cashfree's own docs/blog/newsroom pages fetched on 27 Oct 2026 (docs are the primary source). Docs pages are frequently revised; several internal inconsistencies are flagged inline. Third-party press coverage was not retrieved (search returned only Cashfree-owned pages plus MCP directories).

## 1. Payment Gateway, Payment Links, Checkout, UPI intent/QR, Subscriptions/AutoPay/eNACH, Easy Split, Refunds: what each does and sandbox support

### Takeaway
Sandbox covers the full PG order lifecycle (cards, UPI via fake `@gocash` VPAs with ~24 distinct outcomes, netbanking, wallet, EMI, paylater, TPV, preauth), Payment Links, Easy Split with settlement simulation, and Subscriptions (with real constraints: periodic subscriptions cannot be force-advanced, 25h pre-debit gap). The most "money-moving" PG actions an agent can do in sandbox are create_order, pay-order (UPI/card/netbanking), create_refund, payment links, simulate_payment, vendor split settlement simulation, and on-demand subscription charges. UPI QR/intent have no documented sandbox test data.

### Cited Findings
- Auth: headers `x-client-id`, `x-client-secret`, `x-api-version` (examples use `2025-01-01`; Easy Split and subscriptions docs use `2026-01-01`). Sandbox base `https://sandbox.cashfree.com/pg/{resource}`. Test and prod keys separate; PG keys do NOT work for Payouts/Secure ID. PG allows one key pair at a time; test PG keys auto-generated with no 2FA; production keys need 2FA. 401 `authentication_error` on wrong key/env. — [Cashfree auth docs](https://www.cashfree.com/docs/api-reference/authentication.md)
- Sandbox payment modes: card, netbanking, UPI, wallet, credit/debit EMI, PayLater, cardless EMI; netbanking is a single "TEST Bank"; wallet is one generic test wallet; PayPal and bank transfer NOT supported in sandbox; sandbox TDR does not reflect production rates. — [Sandbox environment](https://www.cashfree.com/docs/payments/online/resources/sandbox-environment.md)
- Test data: card OTP `111000`, expiry `03/2028`, CVV `123`, name `Test`; sample cards e.g. Visa credit `4444333322221111`, Mastercard `5105105105105100`, RuPay debit `6074825972083818`; netbanking code `3333`; PayLater/cardless EMI mobile `8714268343` (PAN `1234`, OTP `777777`, cardless EMI min Rs 1,000). — [PG test data](https://www.cashfree.com/docs/api-reference/payments/data-to-test-integration.md)
- UPI sandbox VPAs (all `@gocash`): `testsuccess`, `testfailure`, `testinvalid`, `testdeclineuser`, `testexpired`, `testtimeoutbank`, `testremitterunavailable`, `testinsufficientfunds`, `testbankdeclined`, `testriskflagged`, `testnetworkerror`, `testinvalidpin`, `testuserdropped`, `testfraud`, `testdebitfailed`, etc. (about 24 failure/success modes - good for demoing agent retry/recovery logic). TPV: `testtpvsuccess@gocash` / `testtpvfail@gocash` with account `1111222233`, IFSC `TEST0001234`. — [PG test data](https://www.cashfree.com/docs/api-reference/payments/data-to-test-integration.md)
- Preauthorisation: create order with `order_note: preauth_transaction`, then capture/void via Preauthorisation API; card and UPI via Order Pay `link` channel. Token Vault test BINs available. — [PG test data](https://www.cashfree.com/docs/api-reference/payments/data-to-test-integration.md)
- UPI QR and UPI Intent: no test data is listed on the test-data page (documented as gap). Cashfree HERE (chat plugin) lists UPI Intent, UPI QR, cards, net banking as widgets with a sandbox/production `environment` flag. — [Cashfree HERE](https://www.cashfree.com/docs/tools-ai/cashfree-here.md)
- Payment Links: UPI links max Rs 1 lakh each (use "All payment methods" for more); partial payments with a minimum amount (not allowed for UPI); expiry settable; share via SMS/email/WhatsApp; `link_notify`; webhooks for complete/partial/cancelled/expired; cancel but not delete; `link_id` up to 50 chars; TPV links; auto-activated with a PG account; bulk Batch needs Support Form activation; link flow testable in sandbox. No min link amount documented. — [Payment Links FAQ](https://www.cashfree.com/docs/help/payment-links/faqs/faqs.md)
- PG rate limits per minute, production: Create Order 200 (account), Get Order 400, Get Payments 100, Get Payments by ID 130, Pay Order 100 (per IP), Get Settlements 30, Initiate Refund 100, Get Refund 30. Sandbox: Create Order 30, Get Order 60, Get Payments 30, Pay Order 30 (IP), Get Settlements 20, Initiate Refund 30, Get Refund 60. — [PG rate limits](https://www.cashfree.com/docs/api-reference/payments/rate-limits.md)
- Idempotency: send `x-idempotency-key` (UUID) on mutating requests (payment creation, refunds), reuse only when retrying the same request; backoff 1s doubling with jitter, 3-5 retries; avoid concurrent requests from one account; rate-limit headers `x-ratelimit-retry/remaining/reset` and HTTP 429. — [API best practices](https://www.cashfree.com/docs/api-reference/api-best-practices.md); header names also listed at [rate limits](https://www.cashfree.com/docs/api-reference/rate-limits.md) as `X-RateLimit-Limit/Remaining/Reset` (casing/name differs between the two pages).
- Easy Split (marketplace split, vendor settlements): setup = send `x-api-version: 2026-01-01`, call Enable Easy Split (202, async, auto-provisions a bank vendor and a UPI vendor `success@upi`), poll status until `ACTIVE` (other values `HOLD`, `NOT_ACTIVE`, `RISK_APPROVAL_PENDING`, `RISK_REJECTED`), copy vendor IDs from dashboard, create order with `order_splits`, then call Simulate Vendor Settlement (targets `INITIATED`/`SUCCESS`/`FAILED`) using `merchant_order_ids` or `txn_time`. Reversals cannot be simulated. Vendor settlement webhooks (`VENDOR_SETTLEMENT_*`) only on webhook version `2025-01-01` and each event must be subscribed separately. Test bank accounts include success, failed-at-bank, invalid IFSC/account, "success later reversed", and name-mismatch (Jon D vs John Doe). — [Easy Split test data](https://www.cashfree.com/docs/payments/split/data-to-test.md)
- Subscriptions: modes are cards (Indian + international), eNACH, UPI AutoPay, physical NACH; types PERIODIC and ON_DEMAND; plans via dashboard/API; Subscription Payment Form for no-code collection. — [Subscriptions intro](https://www.cashfree.com/docs/payments/subscription/introduction.md)
- Subscription sandbox: PERIODIC subscriptions cannot be forced from INITIALIZED to PENDING in sandbox (happens only on billing date); ON_DEMAND can be charged immediately with `POST /pg/subscriptions/pay` (`subscription_id`, `payment_type: CHARGE`); webhook version `2026-01-01`; UPI AutoPay must be activated separately for sandbox and production and is not self-serve; no failure simulation documented. — [Subscriptions FAQ](https://www.cashfree.com/docs/payments/subscription/faq.md)
- Subscription limits: UPI AutoPay Rs 15,000 max without AFA, Rs 1,00,000 with AFA (AFA needs Support Form for charges of Rs 15,000+; UPI PIN each charge); Rs 0 mandate not allowed for UPI (Rs 1 deducted); pre-debit notification requires 25h gap before charge (sandbox and prod); eNACH max Rs 1 crore, authorisation 24-48h, no auto-retry (max 3 manual retries/cycle), savings/individual proprietor current accounts only; scheduled charges T+2 to T+14 only for cards, charge date must be <14 days out; UPI AutoPay T+1 charges only until 20:59. Two tables conflict on Indian card AFA limits. — [Subscriptions FAQ](https://www.cashfree.com/docs/payments/subscription/faq.md)
- Refunds via API: `createRefund`/`getRefund`/`getAllRefunds` exist in the Agent Toolkit; `create_refund`/`get_refund` in the hosted MCP. Sandbox refund behaviour is not documented on the sandbox page. — [Agent Toolkit](https://www.cashfree.com/docs/tools-ai/cashfree-agent-toolkit.md), [MCP server](https://www.cashfree.com/docs/tools-ai/mcp-server.md)
- Dev Studio (sandbox playground) and Postman collections exist. — [AI stack overview](https://www.cashfree.com/docs/tools-ai/overview.md)

### Inferences
- Best sandbox-demoable "money moves" in PG: UPI success/failure matrix (`@gocash` VPAs) driving an agent that retries, switches mode, or issues refunds; Easy Split vendor settlement with simulated INITIATED/SUCCESS/FAILED; on-demand subscription charge.
- An agent demo cannot show a real periodic mandate cycle in sandbox in one day (periodic transition is date-gated; PDN 25h gap); use ON_DEMAND.
- UPI AutoPay needs a non-self-serve activation in sandbox: request before the buildathon or avoid.

### Gaps
- Dedicated page for Payment Forms (sandbox support), Checkout SDK specifics, UPI QR/intent sandbox behaviour, simulate-payment endpoint request/response, and sandbox refund semantics were not retrieved.
- Min/max order amounts for PG orders not found (only the Rs 1,000 cardless EMI minimum and Rs 1 lakh UPI link cap).
- eNACH sandbox mandate simulation not documented.

## 2. Cashfree Payouts: bank/UPI/VPA transfers, bulk, beneficiary validation, payout links, scheduled payouts, sandbox, approvals

### Takeaway
Payouts V2 has a rich sandbox with deterministic outcomes keyed to magic account numbers/VPAs (success, failure, pending-then-success/failure, success-then-reversed, 25s timeout), so an agent can demonstrate real transfer-state handling without real money. Approval flows exist (batch approval, held risky transfers) but are optional/enabled on request; scheduled payouts are not documented as an API feature (only Relay's schedule trigger).

### Cited Findings
- Base URLs: production `https://api.cashfree.com/payout`, test `https://sandbox.cashfree.com/payout` (V2). V1 test host `payout-gamma.cashfree.com` is for the deprecated V1. — [Payouts V2 overview](https://www.cashfree.com/docs/api-reference/payouts/v2/payouts-api-v2-new.md), [Getting started](https://www.cashfree.com/docs/api-reference/payouts/getting-started-with-payouts-apis.md)
- V2 endpoints: Create/Get/Remove Beneficiary; Standard Transfer (async by default); Get Transfer Status; Batch Transfer and Get Batch Transfer Status; "Validate Payout" (checks UPI VPA or phone and returns a single-use transfer token) and "Process Validated Payout". After a 5XX do not re-initiate; check status first. — [Payouts V2 overview](https://www.cashfree.com/docs/api-reference/payouts/v2/payouts-api-v2-new.md)
- Auth: separate Payouts/Secure ID keys (up to 10, shared) from dashboard Payouts > Developers > API Keys; optional 2FA: IP whitelist (IPv4, max 25, production needs Cashfree approval, test does not) or Public Key signature (`X-Cf-Signature` = Base64(RSA-encrypt(`clientId.unixTimestamp`)), with `X-Client-Id`). — [Getting started](https://www.cashfree.com/docs/api-reference/payouts/getting-started-with-payouts-apis.md)
- Transfer modes: IMPS (instant, 24x7, up to Rs 5 lakh), NEFT (about 2h, 1 AM-6:45 PM working days, default above Rs 2 lakh), RTGS (via Payout Wallet note), UPI (24x7, up to Rs 1 lakh; bank limits Rs 10k-1 lakh), cards (instant for IMPS-on-card banks, else up to 48h), Paytm wallet (up to Rs 1 lakh, needs beneficiary KYC), Amazon Pay (up to Rs 10,000). Batch transfers are for bank transfers only. UPI payouts not available via Payout Wallet (CF_WALLET); need Connected Banking. Minimum amounts not specified. — [Payout methods](https://www.cashfree.com/docs/payouts/payouts/make-payouts/payout-methods.md), [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md)
- Sandbox rules: test values only work with test keys; test mode simulates but does not process with banks; each payment mode and validation must be enabled by Cashfree on both test and prod; OTP always `111000`; no SMS. — [Payouts test data](https://www.cashfree.com/docs/payouts/payouts/integrations/data-to-test.md)
- Sandbox bank accounts (acct / IFSC): `026291800001191`/YESB0000262 success; `00011020001772`/HDFC0000001 success; `1233943142`/ICIC0000009 success; `026291800001190`/YESB0000262 invalid account; `1234567890`/ICIC0000001 invalid IFSC; `007711000031`/HDFC0000077 pending; `00224412311300`/YESB0000001 pending then success; `7766666351000`/YESB0000001 pending then failure; `7766671735000`/SBIN0000004 success then reversed; `02014457596969`/CITI0000001 success then reversed; `34978321547298`/KKBK0000001 timeout after 25s then success (docs suggest 10s client / 30s server timeout). Note one doc lists `000100289877623`/SBIN0008752 as Success and another (Verification test data) as "Failed at bank". — [Payouts test data](https://www.cashfree.com/docs/payouts/payouts/integrations/data-to-test.md); conflict with [Verification test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- Sandbox UPI/wallet: `success@upi` success, `failure@upi` failure; wallets: phones 9999999999/8888888888 Paytm success, 7777777777/6666666666 AmazonPay success. Alternate beneficiary identification (phone + card last-4 `1862`, or phone + name "John Snow") has defined success/failed/pending rows. — [Payouts test data](https://www.cashfree.com/docs/payouts/payouts/integrations/data-to-test.md)
- Lifecycle: sync statuses Pending, Success (can later become Reversed), Failed, Reversed, Rejected (high-risk, blacklist, or smart limits); async: Received then Rejected if bene details wrong; Failed debits reversed by bank within 24h. — [Lifecycle](https://www.cashfree.com/docs/payouts/payouts/make-payouts/lifecycle.md)
- Approvals/controls: batch transfers can require approval before funds move (optional, enabled on request; "Approve Batch" tab; per transfer or per file). Payout Protect holds risky transfers for manual approve/block, with ML anomaly detection, blacklists, ATO detection and Smart Rules velocity limits (count and cumulative amount). Webhook events `TRANSFER_APPROVED`, `TRANSFER_REJECTED` exist. — [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md), [Payout Protect](https://www.cashfree.com/docs/payouts/payout-protect/payout-protect.md), [Payout webhooks](https://www.cashfree.com/docs/payouts/payouts/make-payouts/webhooks.md)
- Payout links: Cashgram sends a payout link by WhatsApp/email/SMS so the recipient enters bank/UPI details; single or batch via dashboard; limits, expiry, sandbox status not stated on the page; Cashgram has its own test data page and Cashgram webhooks use the legacy V1 form-encoded signature. The local MCP repo exposes Cashgram create/deactivate/status tools. — [Cashgram](https://www.cashfree.com/docs/payouts/cashgram/cashgram.md), [Cashgram test data](https://www.cashfree.com/docs/payouts/cashgram/integration/data-to-test-integration.md), [cashfree-mcp repo](https://github.com/cashfree/cashfree-mcp)
- Other payout products listed in docs index: Pay2Phone (payout to phone number), OneEscrow, Payout fund sources, Payouts Direct (pays from linked bank, no wallet; no card/UPI/wallet). — [llms.txt](https://www.cashfree.com/docs/llms.txt), [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md)
- Throughput claim: bulk up to 10,000 transactions per minute (not an API rate limit); no documented payouts API rate limit or idempotency rule found on fetched pages (`transfer_id` is the de facto business key per webhook guidance). — [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md), [Webhook reliability](https://www.cashfree.com/docs/api-reference/webhooks/reliability-and-operations.md)
- Wallet withdrawals: max 3/day, to registered business bank only, non-reversible; wallet recharge via virtual bank accounts (UPI recharges not accepted). Payouts only for registered businesses and require business PAN. — [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md), [Account activation](https://www.cashfree.com/docs/help/account/account-activation.md)
- Relay (dashboard no-code agent) supports schedule-triggered vendor payouts and human approval for high-value refunds via email/Slack; sandbox not mentioned. — [Relay overview](https://www.cashfree.com/docs/tools-ai/relay/overview.md)

### Inferences
- The sandbox "pending then reversed/failed" accounts let an agent demonstrate reconciliation, reversal handling and human-in-the-loop approvals convincingly; likely the most distinctive payout demo.
- "Scheduled payouts" would be agent-side logic (cron + Standard Transfer) rather than a Cashfree API feature.
- Payout mode enablement and Payouts account in test may need Cashfree to enable modes (per docs), so request early.

### Gaps
- No documented Payouts rate limit, min amount, idempotency key semantics, or scheduled-transfer API found.
- Whether a sandbox payout wallet balance is pre-funded is not stated.
- Payouts V2 "beneficiary validation" for bank accounts is via Secure ID (Section 3); V2 Validate Payout covers UPI/phone only.
- Full Cashgram sandbox behaviour/limits not retrieved.

## 3. Cashfree Verification Suite / Secure ID: APIs and sandbox availability

### Takeaway
Secure ID has broad API coverage and a deterministic mock layer in TEST (inputs drive outcomes; OTP fixed `111000`), so an agent can run KYC/verification gates before payouts. Reverse penny drop, DigiLocker and Aadhaar offline KYC have little or no documented mock data, so treat them as risky for a one-day demo.

### Cited Findings
- Product areas: KYC Stack (bank, IFSC, PAN, Aadhaar, DigiLocker), Biometric KYC (liveness, face match, name match), Smart OCR, Video KYC, 1-Click Onboarding, OVDs (Voter ID, DL, RC, Passport), Know Your Business (GSTIN, CIN, Udyam). — [Secure ID intro](https://www.cashfree.com/docs/secure-id/introduction.md)
- API list includes Bank Account Verification (sync/async V2), IFSC, Reverse Penny Drop, UPI Penny Drop, PAN Lite/360, Name Match, Face Match, Face Liveness, GSTIN, GSTIN-with-PAN, CIN, Udyam, Mobile 360, KYC Links, Video KYC, E-sign, Geocoding. Sandbox/prod is determined by credentials. — [VRS overview](https://www.cashfree.com/docs/api-reference/vrs/overview.md)
- Test data rules: only listed data works; SMS unavailable, OTP `111000`; outcomes driven by input values; image APIs succeed with any valid image. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- Bank account + name scoring: account `026291800001191` with "JOHN DOE" gives 100 DIRECT / 85 GOOD / 70 MODERATE / 38 POOR for "john doe"/"john d"/"j doe"/"jane d"; same pattern for TOM WELLS (`1233943142`) and BOB HOPE (`388108022658`). — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- UPI Penny Drop VPAs: valid `success@upi`, `valid@upi`, `valid@ybl`; invalid `invalid@upi`, `incorrect@upi`, `invalid@ybl`; expired `expired@upi`, `expired1@upi`, `expired@ybl`. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- PAN valid: ABCPV1234D, XYZPP4321W, AZJPG7110R (individual), ABCCD8000T, XYZHP2000L, AAAHU4383C, AMJCL2021N (business); invalid: DEFPV0126D, TUVPP5678W, LMNCD8010T, EFGHH2020L. GSTIN valid e.g. `29AAICP2912R1ZR`, `27ABCFGH5678D1Z`; invalid `29AAIZP2912R1ZR`, `05BBICA2912R1ZR`. GSTIN-with-PAN `DUMPY1001A` success, `DUMPY1030A` unavailable. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- Aadhaar numbers valid `655675523712`, `655675523711`; invalid `655675523710`, `655675523709`; Aadhaar masking succeeds with a valid image. Name match: JOHN DOE vs JOHN DOE = 1.0 DIRECT; vs JOHN DE 0.93; JOHN 0.77; J DO 0.53; DO 0 NO_MATCH. Face match: any valid image succeeds. Face liveness: `verification_id` prefixes 2222/3333/4444 yield MULTIPLE_FACES/FACE_NOT_DETECTED/REAL_FACE_NOT_DETECTED, others success. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- DigiLocker: only "verify account" mock (mobiles 9988xxxxxx = VALID); full DigiLocker document-fetch mock not documented. Other mocks: Mobile 360 (9999999999 success, 8888888888 not found), CIN, Udyam, Passport (`PA1...` success, `PA0...` invalid), Voter ID, DL, vehicle RC, Video KYC OTP `123456`, 1-click onboarding phone 9999991234 OTP 1234. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- Reverse penny drop: no dedicated test-data section on the test-data page. — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md)
- Rate limits (per merchant account, 429 on excess): Standard 100 TPM (bank account verification, UPI penny drop, name match, face match, IFSC, GSTIN, PAN 360, Smart OCR, Mobile 360, Video KYC etc.); Medium 200 TPM (DigiLocker URL/status/document, Reverse Penny Drop create/details, KYC link, Verify PAN Sync, IP); Restricted 5 TPM (Verify PAN in Bulk). — [Verification rate limits](https://www.cashfree.com/docs/api-reference/vrs/v2/verification-rate-limits.md)
- Secure ID needs enablement: required features must be enabled by Cashfree on TEST and PROD. Secure ID uses the Payouts-style key set (shared up to 10 keys). — [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md), [auth docs](https://www.cashfree.com/docs/api-reference/authentication.md)
- Hosted MCP/local MCP: local repo exposes only 5 SecureID tools (name-match, KYC link generation/status, static link management). — [cashfree-mcp repo](https://github.com/cashfree/cashfree-mcp)
- Mule Sentinel (risk scoring of applicants before account creation using identity, telecom, digital and payment signals) was launched at GFF 2026; API/sandbox availability not stated. — [GFF launches blog](https://www.cashfree.com/blog/gff-product-launches-2026/)

### Inferences
- A safe "verify-then-pay" agent pattern: UPI penny drop / bank account verify (name score threshold) -> approve -> payout; all mockable end-to-end in sandbox with magic values.
- Same account numbers (`026291800001191`, `1233943142`) serve both Secure ID name-match and Payouts success cases, making a coherent end-to-end demo possible.

### Gaps
- Reverse penny drop and DigiLocker document-fetch/Aadhaar offline-KYC sandbox behaviour not documented in retrieved pages.
- Secure ID base URL/IP whitelisting/signature specifics not retrieved (auth page did not cover VRS).
- Whether Verification (for individuals/hackathon teams) is enabled by default on a new test account is unclear (docs say Cashfree must enable features on TEST).

## 4. Cashfree AI / agentic announcements, MCP server, LLM tooling, Showcase, hackathons

### Takeaway
Cashfree has a mature "AI stack" as of Oct 2026: hosted MCP server (PG + dashboard), local open-source MCP (PG + Payouts + SecureID), Agent Toolkit (npm, OpenAI/LangChain/Vercel AI SDK), Agent Skills (doc packs for coding assistants), Cashfree HERE (in-chat payment widgets), Relay/Spark/Resolve (dashboard agents), and Agentic Payments (UPI Reserve Pay + card tokens + biometrics) launched at GFF 2025 and expanded with Visa x redBus and Mastercard x Yatra at GFF 2026. No external Cashfree hackathon, "Showcase" program or winners list was found.

### Cited Findings
- Hosted MCP server `https://mcp.cashfree.com/mcp`; works with Claude, ChatGPT, Cursor, Claude Code (`claude mcp add --transport http cashfree https://mcp.cashfree.com/mcp`); needs merchant account with owner-level access; OAuth-style login to the Merchant Dashboard; client must be approved from the dashboard. Tools: transactions (`search_transactions`, `get_transaction_details`...), settlements (standard/on-demand/vendor), reports, payment links (`create_payment_link`, `cancel_payment_link`...), orders (`create_order` returns `payment_session_id`), payments, `create_refund`/`get_refund`, and sandbox `simulate_payment`/`fetch_simulation`. The page does not say how to switch hosted MCP between sandbox and production. — [MCP server docs](https://www.cashfree.com/docs/tools-ai/mcp-server.md), [Builders blog](https://www.cashfree.com/blog/cashfree-for-builders-ai-stack-for-the-agentic-payments-era/)
- Conflict: the AI stack overview says the MCP server "connects AI tools to the Payment Gateway, Payouts, and SecureID APIs, with local or remote server options", but the hosted server's tool table lists only PG + dashboard tools. Payouts/SecureID are covered by the local server. — [AI stack overview](https://www.cashfree.com/docs/tools-ai/overview.md) vs [MCP server docs](https://www.cashfree.com/docs/tools-ai/mcp-server.md)
- Local MCP (github.com/cashfree/cashfree-mcp, MIT): env vars `PAYMENTS_APP_ID/SECRET`, `PAYOUTS_APP_ID/SECRET`, `SECUREID_APP_ID/SECRET`, `TWO_FA_PUBLIC_KEY_PEM_PATH`, `ENV` = `sandbox` (default) or `production`, `TOOLS` filter (`pg,payouts,secureid`), `ELICITATION_ENABLED`. Tool counts: PG 25 (links, orders, payments, refunds, settlements, disputes, payment simulation), Payouts 8 (standard + batch transfer, status, authorization, Cashgram create/deactivate/status), SecureID 5 (name match, KYC links). Defaults to sandbox. — [cashfree-mcp repo](https://github.com/cashfree/cashfree-mcp)
- Agent Toolkit (`@cashfreepayments/agent-toolkit`, Node 18+): OpenAI (Chat Completions + Agents SDK), LangChain, Vercel AI SDK; 13 tools: createOrder, getOrder, terminateOrder, createRefund, getAllRefunds, getRefund, orderPayUsingUpi/Netbanking/App/PlainCard/SavedCard, createCustomer, fetchCustomerInstruments; `CFEnvironment.SANDBOX|PRODUCTION`; payouts and verification not covered in the docs page. — [Agent Toolkit docs](https://www.cashfree.com/docs/tools-ai/cashfree-agent-toolkit.md)
- Conflict: the Builders blog describes the toolkit as package `@cashfreepayments/agent-tools-js` with "over thirty tools" including identity checks (PAN, GSTIN, bank account, IFSC, name match, penny drop, video KYC); the docs page lists 13 tools and no verification. ## 5. Webhooks, idempotency, rate limits, amounts, what a demo must avoid

### Takeaway
All main products (PG, Payouts V2, Secure ID, PPI) share one webhook scheme: HMAC-SHA256 over timestamp+raw body, Base64, headers `x-webhook-signature` and `x-webhook-timestamp`. Delivery is at-least-once and unordered, so dedupe on business IDs.

### Cited Findings
- Signature (PG, Payouts V2, Secure ID, PPI): `Base64(HMAC-SHA256(x-webhook-timestamp + rawBody, clientSecret))`, compare to `x-webhook-signature`; use raw body, not re-serialised JSON; no replay window specified (set your own tolerance). Payouts V1/Cashgram: form-encoded, no headers; sort params by key, concatenate non-empty values, HMAC-SHA256 base64 with secret, compared to `signature`. Sign with the secret active when the event was sent; keep the previous secret during rotation. — [Payloads and signatures](https://www.cashfree.com/docs/api-reference/webhooks/payloads-and-signatures.md)
- Payouts legacy docs: use the secret from the oldest active API key. — [Payout webhooks](https://www.cashfree.com/docs/payouts/payouts/make-payouts/webhooks.md)
- Payout webhook events: TRANSFER_SUCCESS (with `acknowledged` 1/0 and `utr`), TRANSFER_APPROVED, TRANSFER_FAILED, TRANSFER_REVERSED, TRANSFER_ACKNOWLEDGED, TRANSFER_REJECTED, CREDIT_CONFIRMATION, BENEFICIARY_INCIDENT, LOW_BALANCE_ALERT. Cashfree polls bank transfer status for 72 hours, after which manual reconciliation is needed. — [Payout webhooks](https://www.cashfree.com/docs/payouts/payouts/make-payouts/webhooks.md)
- Retries: endpoint must be HTTPS and return 200 (3xx counts as failure). PG default up to 3 retries at 2, 10, 30 min; configurable fixed/exponential/custom up to 10 retries. Payouts V2/Cashgram: non-configurable, endpoint auto-disabled after more than 5 consecutive failures (re-enable in dashboard). Delivery is at-least-once, order not guaranteed; dedupe by `cf_payment_id`, `transfer_id` or verification ID; for PG version `2025-01-01` `x-idempotency-key` can also be used. — [Webhook reliability](https://www.cashfree.com/docs/api-reference/webhooks/reliability-and-operations.md)
- Webhook source IPs: sandbox `52.66.25.127`, `15.206.45.168`; production `52.66.101.190`, `3.109.102.144`, `18.60.134.245`, `18.60.183.142` (port 443). — [Webhook reliability](https://www.cashfree.com/docs/api-reference/webhooks/reliability-and-operations.md)
- Webhook versioning: vendor-settlement and subscription webhooks require specific webhook versions (`2025-01-01` for vendor settlement; `2026-01-01` for subscriptions) set in dashboard, separate from `x-api-version`. — [Easy Split test data](https://www.cashfree.com/docs/payments/split/data-to-test.md), [Subscriptions FAQ](https://www.cashfree.com/docs/payments/subscription/faq.md)
- Real-money limits: IMPS Rs 5 lakh, UPI Rs 1 lakh per payout (bank limits Rs 10k-1 lakh), Paytm Rs 1 lakh, Amazon Pay Rs 10,000, UPI payment links Rs 1 lakh, UPI AutoPay Rs 15,000 without AFA. — [Payout methods](https://www.cashfree.com/docs/payouts/payouts/make-payouts/payout-methods.md), [Payment Links FAQ](https://www.cashfree.com/docs/help/payment-links/faqs/faqs.md), [Subscriptions FAQ](https://www.cashfree.com/docs/payments/subscription/faq.md)
- API-key hygiene: never expose keys client-side, use env vars, rotate on compromise. — [API best practices](https://www.cashfree.com/docs/api-reference/api-best-practices.md)
- Dashboard-only Payout Protect and Smart Rules apply as controls in production; fraud blocks surface as `Rejected` status. — [Lifecycle](https://www.cashfree.com/docs/payouts/payouts/make-payouts/lifecycle.md)

### Inferences
- Demo should use test keys only, magic values only, run webhook verification on raw body with a replay window (e.g. 5 min) of its own, and persist processed IDs. Expose webhooks via a tunnel (ngrok etc.); dashboard webhook URL must be HTTPS.
- Avoid: production keys, real beneficiary data (real PAN/Aadhaar/bank numbers of real people - DPDP exposure), showing Aadhaar numbers unmasked, any "agent moves real money without human approval" claim, and live UPI Reserve Pay/Agentic Payments claims that cannot be backed up in sandbox.

### Gaps
- No documented per-transaction minimum for PG orders or payouts; Payouts rate limits absent; webhook delivery timeout value absent.
- PG webhook event list and the PG webhook doc page itself were only summarised (detail pages not fetched).

## 6. Realistic risks: KYC/activation for production vs sandbox in a hackathon

### Takeaway
Sandbox is self-serve for PG, but Payouts/Secure ID/UPI AutoPay/some modes need Cashfree to enable features even in TEST; production needs full business KYC (business PAN, website, bank account, ~24 working hours) and is unrealistic for a one-day buildathon. Plan for sandbox only.

### Cited Findings
- Activation: Collect Payments needs website or app-store URL; Verify and Make Payouts need website URL and mandatory business PAN; also signatory identity (Aadhaar OTP/CKYC/DigiLocker), principal place of business (subject to physical verification), bank account with first transaction being a credit from a KYC-compliant account, entity documents, UBO checks, extra docs for some categories; about 24 working hours after complete documents. Before activation: sandbox only, no real payments. — [Account activation](https://www.cashfree.com/docs/help/account/account-activation.md)
- Payouts available only to registered businesses; Cashfree may set volume limits at activation; payout activation and bank linking are separate steps; production IP whitelisting requires Cashfree approval (test does not). — [Payouts FAQ](https://www.cashfree.com/docs/payouts/payouts/general-faqs.md), [Getting started](https://www.cashfree.com/docs/api-reference/payouts/getting-started-with-payouts-apis.md)
- Test-mode features (payout modes, validations, Secure ID APIs, UPI AutoPay, Batch links, TPV, Easy Split) must be enabled by Cashfree per account in test and/or production; UPI AutoPay "not self-serve". — [Payouts test data](https://www.cashfree.com/docs/payouts/payouts/integrations/data-to-test.md), [VRS test data](https://www.cashfree.com/docs/api-reference/vrs/data-to-test-integration.md), [Subscriptions FAQ](https://www.cashfree.com/docs/payments/subscription/faq.md)
- Easy Split enablement can land in `RISK_APPROVAL_PENDING`/`RISK_REJECTED`; stuck onboarding needs a Support Form. — [Easy Split test data](https://www.cashfree.com/docs/payments/split/data-to-test.md)
- Hosted MCP requires an owner-level merchant account and dashboard approval of the client. — [MCP server docs](https://www.cashfree.com/docs/tools-ai/mcp-server.md)
- Enabling 2FA/viewing production keys needs 2FA; sandbox keys for PG are auto-generated. — [Auth docs](https://www.cashfree.com/docs/api-reference/authentication.md)

### Inferences
- Do account signup and request enablement (Payouts modes, Secure ID features, Easy Split, UPI AutoPay) before the buildathon day; response times are not documented, so allow days and have a fallback (mock mode in code).
- Without activation of Payouts/Secure ID in test, the team can still mock these using documented magic values behind the same interface.

### Gaps
- Time for Cashfree to enable test features for a new account is not documented.
- Whether Cashfree offers a hackathon/event sandbox with pre-enabled products was not found; contacting Cashfree or checking organiser channels is the only route.
